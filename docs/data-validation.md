# 数据校验方案（Data Validation）

> 数据可信度是本产品的护城河。接口数据（AKShare / 东方财富）本质是第三方抓取与清洗，**不能盲信**——必须用官方披露做金标准，逐项校验，才能保证报告的每个数字站得住脚。
>
> 本文沉淀数据校验的方法论与落地策略，是 `src/validation/` 模块的设计依据。

---

## 1. 金标准选择：官方年报 PDF（XBRL 受阻后）

理想金标准是 **XBRL 实例文档**（结构化、解析准确率高）。但经 2026-08-26 实测，公开下载链路在当前网络环境受阻：

| 路径 | 状态 |
|------|------|
| 深交所 XBRL 平台 `xbrl.cninfo.com.cn` | 503 不可用 |
| 上交所 XBRL 旧接口 `listxbrl.sse.com.cn/*.do` | 2015 年可用，已改版为 SPA 页面 |
| 上交所新接口 `query.sse.com.cn` commonQuery | 需摸内部 sqlId，公开资料缺失 |
| 巨潮 XBRL 附件（`.xml/.xbrl/.zip` 后缀） | 全部 404 |

**决策：改用「巨潮官方年报 PDF」做金标准。** 理由：

1. PDF 是证监会指定的官方披露，权威性等同 XBRL
2. 年报 PDF 是**文本版**（非扫描件），pymupdf 可精确提取，不依赖 OCR
3. 落地「文档解析」能力（JD 的硬技能），比 XBRL 更通用（招股书、公告均可解）

> 若后续网络环境改善（如深交所平台恢复、上交所新接口摸清），可无缝切换回 XBRL 作为更高精度的金标准。

## 2. 错误分类：对症下药的前提

接口数据的错误本质分两类，**抓捕策略完全不同**：

| 错误类型 | 特征 | 例子 | 抓捕方式 |
|---------|------|------|---------|
| **系统性错误** | 影响一大批数据，一旦错持续错 | 字段映射错（`ASSET_BALANCE` vs `TOTAL_ASSETS`）、口径错（ROE 加权 vs 期末）、某字段某年开始整体跳变（总股本 bug） | 验**一个标的、任意一年**即可暴露 |
| **偶发性错误** | 只在单点出现 | 某期数据缺失、某年抓取失败、单点脏数据 | 只能**全量**才能保证抓到 |

**核心结论：系统错误靠「验一个标的」就能抓，偶发错误才需要「全量」。** 这决定了校验策略的粒度。

## 3. 校验策略（核心）

### 3.1 为什么「随机挑年份」是最差方案

- 一个标的的历史数据是**纵向**的：2020 年错了不影响 2021 年，随机挑年份会**漏掉偶发错误**，又**不如全量彻底**，两头不占。
- 而字段映射 / 口径错误是**横向**的：影响所有股票、所有年份，**抽 1-2 只股票全历史验一遍**就能一网打尽。

**关键洞察：按「年份」抽样是错的，按「标的」抽样才是对的。**

### 3.2 三层策略 + 定期抽样

| 层 | 时机 | 范围 | 成本 | 目的 |
|----|------|------|------|------|
| ① **字段映射 / 口径校验** | 接数据源时（一次性） | 1-2 个标的，全字段 | 低 | 抓系统性错误，建立「字段白名单」 |
| ② **历史数据全量校验** | 标的首次入池时（一次性） | 该标的全历史 | 中（错位下载年报） | 建立「信任基线」 |
| ③ **日常增量校验** | 每季度数据更新时 | 只验新增的季度/年度 | 极低 | 守住新数据不出错 |
| ④ **定期抽样复查** | 每季度抽 1-2 只 | 全历史复查 | 低 | 防数据源**偷偷改口径/字段** |

**一句话**：「全量」做的是**建立基线**（一次性成本），「增量」做的是**守住基线**（每季度近零成本）。随机抽样既建不了基线，也守不住基线。

### 3.3 全历史校验的「错位采样」

A 股年报「主要会计数据」规范要求披露**近三年对比**，所以单个年报 PDF 自带三年数据。利用这一点可**错位采样**覆盖全历史：

```
2025 年报 → 覆盖 2023/2024/2025
2022 年报 → 覆盖 2020/2021/2022
2019 年报 → 覆盖 2017/2018/2019
... 每 3 年下载一个年报即可拼出全历史
```

神华上市以来约需 7 个年报 PDF 即可覆盖，成本远低于逐年下载。

## 4. 当前实现（`src/validation/`）

| 模块 | 职责 |
|------|------|
| `cninfo.py` | 巨潮公告查询（`hisAnnouncement/query`）+ 年报 PDF 下载 |
| `pdf_parser.py` | pymupdf 解析三大主表：`parse_key_financials`（主要会计数据 7 指标）+ `parse_income_statement`（利润表）+ `parse_cash_flow_statement`（现金流量表）+ `parse_balance_sheet`（资产负债表） |
| `validator.py` | 读接口宽表 → 单位对齐 → 容差 <0.1% 对比 → 校验记录 + 三表 reconcile（差异 >1% 覆盖写回） |

调用方式：

```python
from src.validation import validate, format_report, reconcile_all
result = validate("601088", 2025)   # 下载 PDF + 解析「主要会计数据」+ 对比
print(format_report(result))
reconcile_all("601088", 2025)       # 三表（利润/现金流/资产负债）PDF 金标准 reconcile
```

### 三表覆盖范围（2026-09-02 扩展）

金标准解析从「主要会计数据 7 指标」扩展到**三张主表**：

| 主表 | 解析函数 | 覆盖字段 | 对齐接口表 |
|------|---------|---------|-----------|
| 主要会计数据 | `parse_key_financials` | 营业收入 / 归母净利 / 经营现金流 / 净资产 / 总资产 / 总负债 / 总股本 | —（汇总校验） |
| 合并利润表 | `parse_income_statement` | 营业收入 / 营业成本 / 营业利润 / 利润总额 / 净利润 / 归母净利 / 销售费用 / 管理费用 / 财务费用 / 所得税 | `profit_sheet` |
| 合并现金流量表 | `parse_cash_flow_statement` | 经营现金流净额 / 投资现金流 / 筹资现金流 / 资本开支 / 折旧 | `cash_flow` |
| 合并资产负债表 | `parse_balance_sheet` | 19 字段（货币资金 / 存货 / 应收 / 长短期借款 / 未分配利润 / 归母净资产等） | `balance_sheet` |

**关键指标映射**（PDF 指标名 → 宽表字段）：

| PDF 指标 | 宽表字段 | PDF 单位 | 接口单位 |
|---------|---------|---------|---------|
| 营业收入 | `operating_revenue` | 百万元/元 | 亿元 |
| 归属于本公司股东的净利润 | `net_profit_parent` | 百万元/元 | 亿元 |
| 经营活动产生的现金流量净额 | `ocf` | 百万元/元 | 亿元 |
| 归属于本公司股东的净资产 | `total_equity` | 百万元/元 | 亿元 |
| 资产总计 | `total_assets` | 百万元/元 | 亿元 |
| 负债合计 | `total_liabilities` | 百万元/元 | 亿元 |
| 期末总股本 | `share_capital` | 百万股/股 | 亿股 |

> 年报 PDF 单位因公司而异（神华「百万元」、茅台「元」），`_detect_unit` 自动识别。字段名也可能带序号前缀（「一、营业收入」「减：营业成本」）或跨行断开（茅台「筹资活动产生的现金流\n量净额」），解析器均已自适应处理。

## 5. 已验证结论（神华 2025 年报）

**6 个金额指标完全一致（差 0.0000%）** —— 接口财务数据可信：

| 指标 | 官方年报 | 接口 | 结果 |
|------|---------|------|------|
| 营业收入 | 2949.16 亿 | 2949.16 亿 | ✅ |
| 归母净利润 | 528.49 亿 | 528.49 亿 | ✅ |
| 经营现金流净额 | 750.59 亿 | 750.59 亿 | ✅ |
| 总资产 | 6277.61 亿 | 6277.61 亿 | ✅ |
| 总负债 | 1463.10 亿 | 1463.10 亿 | ✅ |
| 归母净资产 | 4091.07 亿 | 4091.07 亿 | ✅ |

**捕获一个真实 bug**：分红接口 `stock_fhps_detail_em` 的「总股本」字段，2025 年报跳涨到 **216.89 亿股**（2017-2024 稳定 198.69），官方年报明确 **198.69 亿股** → 接口数据源错误，验证模块成功拦截。

**口径发现**：接口 ROE 12.92% 对应官方「期末净资产收益率」12.9%，非「加权平均」12.76%，对比时须对齐口径。

## 6. 落地路径（Roadmap）

- [x] **字段白名单**：验证通过的字段进白名单，日常只监控白名单字段的新数据 + 字段映射变更
- [x] **总股本修正**：数据层对股本改用资产负债表 `share_capital`（分红接口 `total_shares` 有 bug）
- [x] **三表金标准扩展**：从「主要会计数据 7 指标」扩展到利润表 + 现金流量表 + 资产负债表全字段
- [x] **三表 reconcile**：差异 >1% 自动用 PDF 值覆盖写回 parquet + 落盘记录
- [x] **测试套件**：`tests/` 单元 + 集成测试（含 PDF 金标准解析一致性回归）
- [ ] **全历史校验**：错位采样扩展（神华 2007 至今 + 茅台），建立信任基线
- [ ] **增量校验**：季度更新引擎触发时，自动校验新增报告期
- [ ] **抽样复查**：每季度随机抽 1-2 只标的全量复查
