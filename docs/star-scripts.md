# fqf 面试 STAR 自述稿

> 版本：v1.0（2026-09-10）
> 用途：**把"做了什么"翻译成"能讲的故事"**，覆盖行为题 + 开场自我介绍 + 软证据补全。
> 与 `interview-narrative.md` 的关系：那份是「讲什么」（技术深度+口径校准），这份是「怎么讲故事」（叙述能力+软证据占位）。
> 配合 `code-review-guide.md`：STAR 故事里提到的代码细节，去那份指南对应位置核对。

**用法**：
- 故事 1、3、5 可直接背（结构稳定，硬证据充分）
- 故事 2 是「王牌」（主动诊断+自我修复，最能证明工程判断力，**优先练熟**）
- 故事 4 标 [待口述] 的位置，**面试前必须自己补一遍血肉**——这是软缺口（跨团队推动）

**软证据缺口警示**（60-90K「资深」必问）：
> 潇姐的工作素材里"跨团队推动/带人"的活证据偏弱——fqf 是 solo 项目。故事 4（vLLM 性能排查）是最有可能挖出"协调范海龙要 schema、和组长宗珂沟通改架构"等动作的地方。**面试前 30 分钟，找潇姐口述补齐 [待口述] 部分**。

## 故事 1 · fqf 数据管道从零搭建（项目总览，最先讲）

**Situation**
我做价值投资（A 股+港股），需要每季度更新的"一页决策依据"——看估值分位、ROE/净利率/分红比例、商业模式、行业地位。但市面没有现成产品：券商研报带主观判断、Bloomberg/Pittoo 国内用不到、自己拉数据又要应对接口脏、指标口径不统一、跨年数据对不上。**缺的不是数据，是"可信、客观、可复用的个人数据基础设施"。**

**Task**
从零搭一个端到端数据管道，覆盖 6 只跟踪标的（茅台/神华/格力/交行/腾讯/泡泡玛特），做到：
- 数据**可信**（不是接口原样落盘就完事，要交叉校验）
- 报告**客观**（零观点铁律，无目标价/多空/买卖建议）
- 流程**可重跑**（季度财报季一键刷 6 只标的不需人工修）

**Action**（5 段管道 + 4 层校验）
1. **多源接入按类型选源**——东财取财务三表、腾讯取实时行情、百度取十年估值、巨潮年报 PDF 当金标准；不是主备切换（mootdx 备用源只有注释没实现，坦诚承认）
2. **DuckDB + PG 双库分层**——raw 层 11 张 parquet（接口原样，单位元），mart 层 3 张宽表（annual 63 列×142 行 / quarter 16 列×48 行 / segments 96 行×6 列，单位亿）。**raw 保持接口原始值、修正只发生在 mart（重拉幂等无害）**
3. **四层质量校验**——PDF 金标准（巨潮 vs 接口，>1% 自动回写）/ 结构+会计恒等式 / Beneish M-Score 造假检测 / PushPlus 告警。**分层调度原则**：日更只跑轻量校验（行情脏了影响小）、季更跑全量四层（财报脏了影响大）
4. **服务化 + 报告渲染**——FastAPI 7 端点（只读 mart 层 + metrics 白名单防注入）+ HTML 报告 + 小红书长图（手机 390px 逻辑宽，导出 1170px 高清）
5. **Airflow 双 DAG 调度**——日更 DAG 抓行情、季更 DAG 抓财报；Dockerfile 不 COPY 源码、compose 用 volume 挂载，改源码不用重建镜像

**Result**
- **代码规模**：26 模块、5200 行、86 项测试全通过
- **报告覆盖**：年度 33 年（1993-2025）、季度近 8 季、估值序列 1462 行日频
- **真实闭环证据**：神华 2025 收购杭锦能源触发"同一控制下企业合并追溯重述"，东财接口总资产报 **9038 亿**，PDF 金标准报 **6278 亿**（差 44%）。校验自动按 >1% 容差回写修正，现在 mart 表里神华 2025 总资产就是 **6277.6 亿**，等于官方口径

**讲法要点**：先讲为什么做（不是玩具），再讲怎么分层（5 段+4 层），最后甩闭环数字（9038→6277.6）。面试官 90% 会追问 PDF 校验怎么做的——切到故事 2。

## 故事 2 · 数据一致性断裂自我诊断 + 治本修复 ⭐ 王牌

> 这是 STAR 稿里最值钱的故事，能证明"我主动诊断过系统性问题、亲手治本修了"。**优先练熟、主动讲出来比任何一条简历都值钱**。

**Situation**
review 自己管道时（2026-09-04），用文件修改时间追出一条数据一致性断裂：
- 9/3 校验层用 PDF 金标准把神华 2025 总资产从接口错误值修正成 **6277.6 亿**
- 9/4 重建数仓，raw 层挂的是修正后的正确值
- **后来重新拉取数据，磁盘 parquet 被覆盖回错误的 9038 亿，但数仓没重建，留着旧正确值**

结果：`data/raw/601088/balance_sheet.parquet`（磁盘）= **9038 亿**（错），`DuckDB raw.balance_sheet` = **6277.6 亿**（对）——**同一份数据两个地方不一致**。

**Task**
不是回滚这一次，是**追出根因 + 改铁律**，让这种事以后不会发生。

**Action**（4 步治本）
1. **用文件 mtime 倒查**——`fs.stat().st_mtime` 拉时间线，确认是「重拉 → 落盘 → 落库」链路缺「重拉后必须重建数仓」的编排保证，**不是靠猜**。
2. **发现 3 个工程判断错位**：
   - 拉取→落盘→落库链路缺编排保证
   - 校验成果会被重拉静默抹掉（reconcile 修正值被 fetch_stock 重拉错误值覆盖，重拉后没触发重新校验）
   - 测试断言站错立场——`test_pdf_parse_matches_api` 还在坚持「PDF 值 == 接口值」，但接口值恰恰是错的，**断言方向反了**
3. **定新铁律**：raw 层**永远保持接口原始值、永不修正**；修正只发生在 mart 层读 raw 之后统一应用；测试金标准改成「PDF 解析值 == 硬编码官方值」而非「== 接口值」
4. **重构 reconcile**——reconcile 不再写回 raw parquet，只生成修正记录；`adapter.load_raw` 读 raw 后应用修正。这样 raw 重拉幂等无害、修正成果不被抹掉

**Result**
- 神华 2025 总资产从接口 9038 亿修正成 **6277.6 亿**（官方口径）
- 治本修了数仓铁律，**这类问题以后不会再发生**
- 加了 9 项回归测试锁住新铁律

**讲法要点**：
- 三段式证据要全：「诊断出来→根因→治本修」，不是「我做了校验」
- 「主动发现自己的 bug、用文件 mtime 追根因、还发现测试断言方向反了」——**这三件事连在一起讲，是资深 vs 中级的分水岭**
- 数字背熟：9038 亿、6277.6 亿、9 项测试、9/3-9/4 时间线

**追问预演**：
- "你怎么发现磁盘和数仓不一致的？" → 答：review 时用 mtime 倒查
- "为什么断言方向反了？" → 答：测试在守卫"接口正确性"而不是"PDF 正确性"，源和标尺选反
- "raw 永存原始值的代价是什么？" → 答：重拉时接口错误值会进 raw，但 mart 读后会自动应用修正记录；代价是必须保证 reconcile 链条不挂，挂了会暴露错误值

## 故事 3 · AI 合规分层架构决策（产品判断 + 决策权衡）

**Situation**
我在做 fqf 时遇到一个产品哲学冲突：AI 能大幅提升分析质量（多视角对比、自动风险扫描），但 AI 生成投资建议（目标价/多空/买卖）是合规红线——公开版不能含这些内容，否则违规。**如果一刀切删 AI 主观输出，分析价值会打折；如果保留，又会越线。**

**Task**
设计一套合规分层架构，**既保留 AI 主观判断的价值，又不越公开版合规线**。

**Action**
按**消费场景隔离**而非**内容隔离**——4 个 LLM 函数各司其职：

| 函数 | 输出 | 去哪 | 合规状态 |
|---|---|---|---|
| `generate_narrative` | 客观公司定性（行业/林奇分类/护城河/逻辑/风险） | 公开报告 | ✅ 无观点，纯数据翻译 |
| `generate_market_view` | 多空视角 | 私有日记 | 第三方视角，非本人观点 |
| `generate_perspective_view` | 四投资人视角 | 私有日记 | 第三方方法视角，非荐股 |
| `generate_action_advice` | 操作建议 | 私有日记 | AI 生成·非本人操作·非荐股 |

加上 prompt 层铁律：「所有结论必须严格基于以下数据，严禁虚构任何财务数字、行业排名、市场份额」。LLM 挂了报告降级为纯数据版，**不阻断主流程**——把 LLM 当可替换节点而非核心依赖。

**Result**
- 公开版（小红书 / ValueLine 一页研报）过合规审计，零目标价/多空/买卖建议
- 私有日记（`journal/`，已 gitignore）保留 4 视角分析价值，**最深的判断写在 `journal.py:275` 注释**：「四个方法论都指向同一结论时是共识，出现分歧时说明这只票看多与看空各有依据，值得本人重点想清楚」
- 这种「场景隔离 vs 内容隔离」的判断，比「我删了多空区」高级——它说明你**理解了合规的边界是「场景」而不是「内容」**

**讲法要点**：
- 把"删 AI 主观输出"和"按场景隔离"摆出来对比，显你的判断力高一档
- 提一句多视角的产品哲学：用方法论分歧暴露自己的盲区

**追问预演**：
- "为什么不让 LLM 给目标价？" → 答：合规红线，没谈判空间
- "LLM 挂了怎么办？" → 答：降级返回 None，报告降级为纯数据版（数值+表格照常出，只是少了叙事文字）。这是把 LLM 当可替换节点的设计
- "私有日记怎么保证不入公开？" → 答：路径在 `journal/` 已 gitignore，且渲染层从 `narrative_data` 之外完全读不到私有内容，**架构层阻断而非流程层约定**

## 故事 4 · vLLM 性能瓶颈排查（生产经验 + [待口述]跨团队）

> 这是最有"跨团队推动"软证据潜力的故事。但具体协调动作（找范海龙要 schema、和宗珂组长沟通改架构等）我从对话记录里挖不出来，**面试前 30 分钟找潇姐口述补 [待口述] 部分**。

**Situation**（已掌握）
我负责生产 K8s/Seldon 部署的向量化与排序服务，目标是 sentence-transformers 向 vLLM API 架构改造。**生产环境出现性能瓶颈**：atapppl4-ganzhouop1-kno 命名空间下的 vLLM Pod，CPU 使用率卡在 40% 压不满、GPU KV cache 使用率 0.0%、sidecar 到 vLLM 的并发连接过少。rank-fgn 排序服务（Flask + gunicorn + bge-reranker-v2-m3，V100 32GB）也跑得慢。

**Task**
排查这 3 个性能症状的根因并修复。

**Action**（已掌握）
1. 排查命令逐层定位——`kubectl exec` 进 Pod、`kubectl logs`、`nvidia-smi`、`curl` 打 sidecar 端口（7000）、主服务 vLLM API 端口——逐步缩小范围
2. 高度怀疑 **gunicorn workers 配置瓶颈**——V100 单 GPU 配 workers=1/threads=1 是单线程，理论上还有并行空间
3. HF tokenizer 并发问题：GUNICORN_THREADS=2 报「Already borrowed」错，**这是 HF tokenizer 不是线程安全的已知问题**。方案是 **threads=1 + TCP 探活**——降并发避免线程争用、TCP 探活弥补单连接故障恢复慢的弱点

**Result**（[待口述]）
- 性能恢复：[待口述具体数字，比如 QPS / 延迟 / GPU 利用率改善]
- 上线：[待口述时间窗口和回滚方案]

**[待口述] 软证据补全（这是面试官最爱问的细节）**
1. **跨团队协调**：排查过程中有没有找同事范海龙要生产 schema/配置截图？怎么沟通的？
2. **架构决策权衡**：threads=1 vs threads=2，是谁拍板的？你自己的判断还是和组长宗珂/同事讨论过？
3. **带人/影响**：这个修复有没有 broadcast 给团队？有没有写文档/SOP 给后续同事？
4. **生产非功能测试**：JD 提到"生产非功能测试"是你负责的，这个性能排查是不是 non-functional test 的一部分？怎么和功能测试分工？

**讲法要点**：
- 技术部分（gunicorn/HF tokenizer/TCP 探活）背熟，这是显你真在生产干过的细节
- 软证据部分必须自己补——面试官问"你怎么协调的""谁拍板的"，没有具体动作就只能背套话
- 如果你确实没协调过任何人，**也别编**——诚实说"这是我独立排查的、性能问题是先在 staging 发现的我自己处理完上线"，这是真实答案也值钱

## 故事 5 · 辞职转型决策（战略 + 个人主动性 + 决策权衡）

**Situation**
在建行金融科技公司干到第 12 年，做后端/算法工程师，工作越来越压顶：
- 长期久坐写代码，颈椎/肌肉劳损+桥本甲状腺炎+胃病史（饭后腹泻）—— 健康亮红灯
- 丈夫长期不给家用、常不在家，育儿和养家主要由我承担
- 工作节奏紧张、下班带娃后精力见底，**期望远程办公获得时间自由度以规律管理个人资产**
- **传统 onsite 路径不适合我的家庭结构**

**Task**
不是"要不要辞职"的二元问题，是**"如何在不裸辞的情况下规划转型路径"**——盘点财务、设计求职/居家双轨收入、6-8 个月体系建设期怎么过。

**Action**（4 步规划）
1. **盘清财务安全垫**：流动资产约 340 万（200 万低风险理财 + 55 万活期 + 90 万基金股票）+ 年租金收入 8 万 + 月家庭支出约 2 万 + 无房贷 → **30 万流动资金可撑 38 个月**，辞职后月净支出约 7,833 元
2. **设计双轨收入**：远程数据工程岗保底（现金流）+ 居家投研产品复利（小红书+小程序）。**不裸辞冒险**，用工作收入养体系建设期
3. **fqf 项目作为求职作品集**：把日常工作技术栈（K8s/vLLM/Seldon/Milvus）映射到 JD 七项要求（多源抓取/PDF 解析/DuckDB+PG schema/Airflow+质量告警/LLM 结构化输出/FastAPI 7 端点/云部署方案），**项目就是 JD 的镜像作品集**
4. **作业化交付**：9/3 提离职、领导延长至 10/17 离职、30 天交接期内完成工作交接文档（vLLM 性能排查/训练案例/版本历史）。**阿姨拖到 10/17 last day 兜底**，避免交接期无阿姨手忙脚乱

**Result**
- 9 月通知期、10/17 last day 已和组长宗珂确认
- 6-8 个月体系建设期规划完整——前 3 个月集中 fqf 数据管道补齐（云实操、dbt、血缘）/ 中期 3 个月内容输出节奏搭建（9 宫格图卡+投研手记+深度长文+景气度扫描帖）/ 后期 2 个月求职冲刺（远程岗为主，B 计划 40-60K 保底）
- 三大账户结构搭建完成——①高股息攒息账户（招行/兴业/成都银行/格力/神华）②主动投研账户（茅台/神华/泡泡玛特深度研究）③指数定投账户（中证A500 + 纳指定投）

**讲法要点**：
- **不要讲成"我因为家庭问题辞职"**——这是私人原因面试官不需要听。讲成"我用 12 年复合背景规划了一条可行路径"
- 把 30 万安全垫 / 38 个月 / 双轨收入 / fqf 作品集四件事**连成一条线**讲，是战略思维的证据
- 不要讲"我在小红书做自媒体"——这是个人副业不加分；讲"我用 fqf 项目作为求职作品集"才是岗位相关的

**追问预演**：
- "30 万够吗？" → 答：月净支出 7833 元 × 38 个月 = 30 万，3 年缓冲，且远程岗一旦拿到就有现金流补
- "如果 6 个月没找到工作怎么办？" → 答：B 计划：投递 3-5 个 40-60K 的中高级数据岗保底；fqf 项目已经是作品集，投中率不低
- "为什么不做全职博主？" → 答：自媒体收入不稳定+合规风险（荐股），和远程数据工程岗比现金流弱

## 软证据补全访谈提纲（10 题，30 分钟，面试前必过）

> 这 10 题的答案挖出来，故事 4（vLLM 性能）和日常"跨团队/带人"软证据就稳了。

1. **vLLM 性能排查**：你有没有跨团队协调过？比如找范海龙要生产 schema、和宗珂组长沟通改 gunicorn 配置、和 MindFormers 团队对接 vLLM 模型路由？
2. **架构决策**：threads=1 vs threads=2 这个降并发的判断是你自己拍板还是和团队讨论？有没有不同意见？怎么权衡的？
3. **影响范围**：这个修复只服务了你的 rank-fgn 服务还是 broadcast 给其他用 vLLM 的同事？有没有写 SOP？
4. **生产非功能测试**：JD 提到的"生产非功能测试"具体包含哪些？性能/混沌/压测？是你一个人做还是有团队？
5. **带新人**：你在建信金科有没有带过新人/实习生？带过几个？怎么带的？
6. **跨团队推动**：fqf 项目里的 PDF 校验、Airflow 双 DAG、DuckDB 分层这些工程决策，有没有和同事/同行讨论过？还是纯 solo 决策？
7. **说服别人**：有没有过"我坚持一个方案、最初别人不同意、最后证明我是对的"的具体场景？
8. **组织贡献**：你在建信金科有没有做过流程改进/工具建设被团队采纳？比如写过内部工具/做过知识分享？
