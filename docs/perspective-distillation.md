# 视角蒸馏 SOP（读书 → 视角 JSON → 投研日记）

> 定位：把一本投资书里的方法「蒸馏」成一个可复用的投资人视角，之后同一份客观数据
> 就能按这个视角自动生成对应风格的投研笔记。这是一条复利流水线。
>
> 铁律（贯穿始终）：视角只是「翻译数据的语言」，不是「编造数据的来源」。
> 所有视角输出都属「第三方方法视角」，非本人观点、非荐股。

---

## 一、为什么这么做

同一份财务数据，格雷厄姆看到的是「安全边际」，林奇看到的是「成长分类」，
巴菲特看到的是「护城河 + ROE」。数据是同一份，结论因方法论而异。

- **数据层**只做一件事：客观、可验证、有来源。
- **视角层**负责「换个角度重新读这份数据」，产出不同风格的结论。
- 这样，「读一本书」就能沉淀成一个可复用的视角，而不是读完就忘。

---

## 二、一个视角的定义（JSON 结构）

视角定义放在 `src/report/perspectives/{id}.json`，结构如下（必填字段带 ⭐）：

```json
{
  "id": "graham",                                    // ⭐ 英文短 id（小写，文件名同名）
  "name": "格雷厄姆",                                 // ⭐ 中文名（用于标题）
  "full_name": "本杰明·格雷厄姆（Benjamin Graham）",   // ⭐ 全名
  "school": "价值投资 · 安全边际流派",                 // 流派标签
  "source_books": [                                   // ⭐ 书单溯源（一句话能查证）
    "《聪明的投资者》(The Intelligent Investor, 1949)",
    "《证券分析》(Security Analysis, 1934, 与多德合著)"
  ],
  "core_belief": "把投资当作一门生意，用安全边际保护本金。",  // ⭐ 一句话核心信条
  "focus_dimensions": [ ... ],                         // ⭐ 关注维度（3-6 条）
  "core_questions": [ ... ],                           // ⭐ 核心问题（3-6 条，逐条回答）
  "metrics_to_watch": [ ... ],                         // ⭐ 该看的指标（3-6 条）
  "tone": "冷静、保守、强调风险控制……",                 // ⭐ 话术风格
  "disclaimer": "格雷厄姆框架推演 · 第三方方法视角，非本人观点，非荐股"  // ⭐ 免责声明
}
```

字段含义：

| 字段 | 作用 | 好坏标准 |
|---|---|---|
| `focus_dimensions` | 这个投资人「盯什么」 | 具体、可对应到数据，而非「关注基本面」这种空话 |
| `core_questions` | 让他「逐条自问」的问题 | 每条都能用数据回答，而不是「这个行业未来怎么样」 |
| `metrics_to_watch` | 落到具体指标 | 尽量用项目里已有的指标（PE/PB/ROE/负债率/现金流等） |
| `tone` | 决定输出的「语气」 | 要能让人一眼看出「这不是通用 AI，是这个人在说话」 |
| `source_books` | 溯源，保证可验证 | 书名 + 年份，最好加作者 |

## 三、蒸馏流程（5 步）

### Step 1：读，并做「方法笔记」

读的时候只记三样东西，其余不记：

1. **他反复强调什么**（→ 成为 `focus_dimensions`）
2. **他拿到一家公司先问什么**（→ 成为 `core_questions`）
3. **他看哪些数字/指标做判断**（→ 成为 `metrics_to_watch`）

> 方法笔记只记「怎么做判断」，不记「他对某只股票的结论」（那是案例，不是方法）。

### Step 2：提炼核心信条

用一句话概括「这个人认为什么是投资里最重要的」。
- 格雷厄姆 → 安全边际
- 巴菲特 → 护城河 + 长期复利
- 林奇 → 公司分类 + 生活里发现好公司

### Step 3：写 JSON

照上面的结构填空。**优先用项目里已经能算出来的指标**（避免视角「要了一个数据层给不出的指标」）。
已有指标参考见 `docs/architecture.md` 的指标清单。

### Step 4：自检（checklist）

写完对着这个清单过一遍：

- [ ] `id` 与文件名一致，全小写英文
- [ ] 每个 `core_question` 都能被「客观数据」回答，不依赖主观判断
- [ ] `metrics_to_watch` 里的指标，项目数据层都能算出来（不引入新数据源）
- [ ] `tone` 足够具体，能区别于其他视角
- [ ] `source_books` 真实可查证（书名/作者/年份）
- [ ] `disclaimer` 明确标注「第三方方法视角 · 非本人观点 · 非荐股」

### Step 5：跑一条验证

```bash
python scripts/journal.py 601088 --force
```

打开生成的日记，看这个新视角的输出是否「像那个人在说话」、有没有编数据。
不满意就回去改 JSON 的 `tone` / `core_questions`，再跑一次。

---

## 四、判断一个视角「好不好」的 3 个标准

1. **能区分**：4 个视角对同一家公司给出 4 种不同的关注点和结论，而不是套话换个壳。
2. **能证伪**：每个判断都落在具体数字上（「PB 分位 2% 太便宜」），而不是「感觉不错」。
3. **不越界**：视角只「读数据」，绝不「编数据」。凡是数据层没有的数字，视角一律不得输出。
