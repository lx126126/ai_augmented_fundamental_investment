# 架构设计文档

> AI 增强基本面投研 · ValueLine 一页研报 + 小程序产品
> 版本：v1.0（2026-08-20）

## 1. 项目概述

为 A 股标的输出 **ValueLine 风格的一页投研报告**，季度更新，最终形态为**小程序上下滑动长图 + 小红书笔记**。代码通过 GitHub 维护。

核心方法论：**格雷厄姆流派（安全边际 / 财务稳健）+ 彼得·林奇六类公司分类**。

---

## 2. 产品定位与报告分层

### 2.1 核心矛盾

一份报告包含两类内容，生成方式不同：

| 类型 | 模块 | 生成方式 |
|------|------|---------|
| 数据可自动生成 | 财务数据（全历史/季度/业务构成/股本）、估值分位、52周区间、机构目标价、造假检测 | 拉取 + 计算，100% 自动化 |
| 深度需人工 | 商业模式、护城河、竞争地位、投资逻辑、季度复盘闭环 | 人工洞见 + 持续跟踪积累 |

### 2.2 报告分两层（漏斗模型）

```
全 A 股 5000+ ── 算法扫描 ──→ 搜索层「数据体检报告」
    （景气度/估值/财务质量，浅层自动化）     │
                                          ↓ 筛出候选
候选池 几十~几百只 ── 跟踪观察 ──→
                                          ↓ 深度研究
跟踪池 5-8 只 ────── 深度研究 ──→ 深度层「深度研报」
    （数据报告 + 商业模式/护城河/投资逻辑/复盘闭环）
```

| 层级 | 覆盖 | 内容 | 生成 | 定位 |
|------|------|------|------|------|
| **搜索层** | 全 A 股 | 数据体检报告（财务全历史、季度、业务构成、估值、52周、机构目标价、造假检测） | 100% 自动，秒级 | 工具 / 引流 / 免费 |
| **深度层** | 跟踪池 5-8 只 | 深度研报（数据报告 + 商业模式、护城河、投资逻辑、复盘闭环） | 数据自动 + 人工洞见 | 内容 / 信任 / 付费 |

**原则**：搜索层保证「数据准确、指标齐全」；深度层保证「洞见 + 复盘闭环」。两者互补，深度不能因为广度而变浅。

## 3. 总体架构（四层）

```
数据层   →  分析层   →  报告层   →  产品层
采集·校验·入库  指标·估值·分类  一页报告·季度更新  小程序·内容分发
─────────────────────────────────────────────────────
        方法论底座：格雷厄姆流派 + 彼得·林奇六类
```

- **数据层**：多源采集 → 文档解析（XBRL/PDF 财报结构化抽取）→ 清洗校验 → 预计算入库（全市场批量 ETL）
- **分析层**：基本面指标、估值分位、林奇六类分类、格雷厄姆质量体检、财务造假检测
- **报告层**：ValueLine 一页 HTML 模板 + LLM 文本生成 + 季度更新引擎 + 跟踪池管理
- **产品层**：微信小程序（搜索即出报告）+ FastAPI 后端 + 内容发布

## 4. 数据层设计

### 4.1 数据源

| 数据 | 主源 | 备用源 | 自然频率 |
|------|------|--------|---------|
| 财报（利润表/资产负债表/现金流） | AKShare | 东方财富 | 季度披露 |
| 行情 / 估值（股价、52周、PE/PB） | AKShare | mootdx / 腾讯 | 每交易日 |
| 机构目标价 / 评级 | AKShare / 东财 | Wind（若有） | 持续更新 |
| 分业务收入构成 | 公司财报 | 东财 | 季度/年度 |
| 股本结构（普通股/优先股） | 财报 | — | 变动时 |

> **文档解析（XBRL / PDF / HTML 结构化抽取）**：财报与公告的原始形态是 PDF / XBRL / HTML，需抽取为可用表格——XBRL（A 股财报标准披露格式，解析三表 + 附注标签）、PDF 财报（招股书/年报，含图片型 PDF 与复杂表格、中英文，规则解析 + LLM 视觉模型兜底）、HTML 公告（巨潮等）。此模块对齐岗位的「文档解析」能力，与金融数据方向天然契合。

### 4.2 预计算方案（关键）

「搜索即出报告」要求秒级响应，**不能用户搜索时才实时拉取**（单股全历史拉取需数十秒且限流）。

正确做法：**后台定时预计算 → 入库 → 搜索时直接渲染**。

```
后台定时任务（分层调度）
  财报数据 ── 季更 ──┐
  行情/估值 ── 周更 ──┼→ 全 A 股预计算 → 入库（DuckDB/PostgreSQL + parquet）
  机构数据 ── 月更 ──┘

用户搜索股票代码 ──→ 从库读取 → 渲染 HTML 长图 ──→ 秒级出报告
```

### 4.3 分层调度频率

| 数据 | 调度频率 | 说明 |
|------|---------|------|
| 财报数据 | **季更** | 跟随财报披露节奏（Q1/Q3 季报、半年报、年报） |
| 行情 / 估值 | **日更 / 周更** | 数据可得、成本低 |
| 机构目标价 / 评级 | **周更 / 月更** | 跟随券商研报节奏 |
| 深度跟踪池 | **季更（全量）** | 年报/中报季全量更新，Q1/Q3 轻量 |

### 4.4 数据库选型

全 A 股 5000+ 只 × 多年财报 ≈ **数百万行**，SQLite 在分析查询与并发下捉襟见肘。

| 场景 | 选型 | 理由 |
|------|------|------|
| 本地开发 + 分析 | **DuckDB** | 嵌入式、列式存储、分析查询快、parquet 原生支持、零运维 |
| 产品层 API（小程序后端） | **PostgreSQL** | 多用户并发、服务化、生态成熟 |
| 文件层 | **parquet + COS** | 原始数据与中间结果归档，云存储 |
| 云数仓（规模化迁移目标） | **Snowflake / BigQuery** | schema 化表格设计与维护、弹性算力，对齐岗位「现代云数据仓库」要求 |

> 分阶段：开发阶段 DuckDB + parquet 本地；产品阶段 PostgreSQL 承接 API 查询，parquet 走 COS 归档。Snowflake/BigQuery 作为规模化后的迁移目标，schema 设计保持与 Postgres 兼容。

### 4.5 数据质量与监控

- 财报数据以公司官方披露为准，逐项校验（模板内「数据校验记录」模块留痕）
- 机构数据标注截至日期与家数
- **数据质量检验**：缺失值 / 异常值 / 口径一致性校验，未通过则告警
- **血缘追踪**：字段级 lineage 标注（源 → 清洗 → 指标），可追溯
- **调度告警**：任务失败 / 延迟告警（Airflow 通知）

> **数据校验方案**（金标准选择、错误分类、三层校验策略、字段白名单）详见 [data-validation.md](data-validation.md)。核心：官方年报 PDF 做金标准，首次全量建基线 + 日常增量守基线 + 定期抽样防漂移。

## 6. 报告层设计

### 6.1 报告生成流程（数据先行）

```
真实财报数据（事实底座，必须拉取）
        ↓
结构化上下文（指标、同比、估值分位、机构数据）
        ↓
LLM 仅生成「文字段落」（商业模式/投资逻辑/风险/复盘）
        ↓
模板渲染 → HTML 长图（1080px 宽 × 高度自适应）
        ↓
Playwright 导图（PNG @2x / PDF）
```

**铁律：LLM 只「翻译」不「编数据」** —— 财务数据必须是拉取的真实值，LLM 只负责把数据讲成投研语言，防止幻觉与失真。

**LLM 工程化**（对齐岗位「LLM 层」要求）：

- **结构化输出**：JSON schema / function calling 约束 LLM 输出，直接落库与渲染
- **RAG**：财报原文 / 研报片段向量化检索，作为生成上下文（复用 Milvus + ES 经验）
- **评估与质量监控**：生成文本与数据一致性校验、幻觉检测、简单评分

### 6.2 模板结构（当前 v1.x）

头部 → 商业模式 → 核心财务数据（年度全历史 + 近两年季度 + 业务收入构成）→ 估值与市场 → 投资逻辑 → 风险 → 机构观点分歧 → 财务造假检测 → 季度复盘 → 数据校验 → 免责页脚

- 财务表 / 季度表 / 业务构成为**数据驱动**（加数据即加行）
- 模板由 `scripts/build_valueline.py` 生成

### 6.3 导图

- `scripts/export.py`：Playwright 截图 PNG 长图（@2x 2160px 超清）+ PDF 长页
- 未来可按需拆分小红书多图卡片（`--split` 参数预留）

## 7. 产品层设计

### 7.1 小程序

- 用户搜索股票代码 → 秒级产出「数据体检报告」（搜索层）
- 跟踪池标的 → 展示「深度研报」（深度层）
- 长图上下滑动浏览

### 7.2 后端服务层（FastAPI）

- **FastAPI** 提供查询 API：股票搜索 → 返回结构化数据 + 报告 HTML
- 服务下游分析师工具与小程序前端
- 生产经验：gunicorn 部署、并发控制、探活（复用公司实战经验）

### 7.3 合规分级（前置约束，非事后补丁）

| 层级 | 内容 |
|------|------|
| **公开端**（小红书/公域） | 只放「数据 + 方法论 + 复盘过程」，结论中性化，不出现目标价、多空、看好看空 |
| **付费端**（小程序/社群） | 完整报告（含目标价、多空、估值判断） |

> 无牌照发布「个股 + 目标价 + 多空」存在非法证券投资咨询风险，公开端必须做内容分级。

## 8. AI-Native 数据管道（技术亮点，兼顾简历）

```
Airflow 调度 → 多源抓取 + 文档解析(XBRL/PDF) → 全市场批量 ETL
        → DuckDB/PostgreSQL 入库(含血缘追踪) → 指标计算 + 造假检测
        → LLM 生成报告文本(结构化输出+RAG) → 模板渲染 → 导图
        → FastAPI 查询 API
```

- **调度**：Airflow（最小 DAG，本地运行，0 成本）或 Prefect / Dagster
- **文档解析**：XBRL / PDF / HTML 结构化抽取
- **LLM 应用**：造假检测 + 报告文本生成（vLLM/Qwen + OpenAI/Anthropic API），结构化输出 + RAG + 评估
- **后端**：FastAPI 查询 API
- **云**：COS / S3 存储；Snowflake / BigQuery 云数仓（规模化迁移目标）
- 此架构覆盖岗位「源数据接入 + 文档解析 + 数仓 + 编排监控 + LLM 层 + 后端 + 云」全部七块核心能力
